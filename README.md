# Co-working Booking API

Асинхронне REST API для керування локаціями коворкінгу та бронювання робочих місць. Адміністратори керують локаціями, типами місць і погодинними тарифами. Користувачі можуть поповнювати внутрішній баланс, шукати вільні місця, створювати та скасовувати бронювання.

Технологічний стек включає FastAPI, Pydantic, SQLAlchemy Async, PostgreSQL, Redis, Alembic, Docker Compose, pytest.

## Локальний запуск

Потрібні Docker і Docker Compose. Команда з кореня репозиторію збирає API, запускає PostgreSQL і Redis та очікує готовності сервісів. API застосовує міграції Alembic перед запуском HTTP-сервера.

```powershell
docker compose up --build -d --wait
```

| Ресурс | Адреса |
| --- | --- |
| Swagger UI | [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) |
| Специфікація OpenAPI | [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json) |
| Перевірка доступності API | [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health) |

Якщо `JWT_SECRET` не задано, API генерує ключ під час запуску. Для збереження чинності токенів після перезапуску можна задати випадковий `JWT_SECRET` у локальному файлі `.env`, який виключено з Git.

## Маршрути та доступ

| Маршрут | Доступ | Призначення |
| --- | --- | --- |
| `POST /auth/register`, `POST /auth/token` | Публічний | Реєстрація з нульовим балансом і видача JWT |
| `GET /auth/me` | JWT | Поточний профіль і роль |
| `/locations`, `/locations/{location_id}` | Адміністратор | CRUD локацій |
| `/locations/{location_id}/desks`, `/locations/{location_id}/desks/{desk_id}` | Адміністратор | CRUD робочих місць у межах локації |
| `POST /wallet/top-up` | JWT | Імітація поповнення внутрішнього балансу |
| `GET /availability` | Публічний | Пошук за параметрами `city`, `starts_at` і `ends_at` |
| `POST /bookings` | JWT | Створення бронювання й списання вартості |
| `POST /bookings/{booking_id}/cancel` | Власник бронювання | Скасування й повернення коштів |

### Сценарій ручної перевірки

1. Через `POST /auth/register` реєструються два облікові записи. Публічна реєстрація призначає роль звичайного користувача.
2. Для локальної перевірки адміністрування роль одного з облікових записів призначається в PostgreSQL. У команді нижче `admin@example.com` відповідає email зареєстрованого облікового запису.
3. У Swagger UI авторизація доступна через **Authorize**. Поле `username` приймає email. Від імені адміністратора створюються локація і робоче місце.
4. Від імені звичайного користувача поповнюється баланс, виконується пошук і створюється бронювання. Тіло запиту на бронювання містить `desk_id`, `starts_at` і `ends_at`. Час передається у форматі ISO 8601 із часовим зміщенням або суфіксом `Z`. Після створення бронювання можна перевірити його скасування від імені власника.

```powershell
docker compose exec db psql -U coworking -d coworking -c "UPDATE users SET role = 'admin' WHERE email = 'admin@example.com' RETURNING id, email, role;"
```

## Правила бронювання

- **Інтервали.** Бронювання використовують напіввідкриті проміжки `[початок, кінець)`. Сусідні бронювання можуть мати спільну межу. PostgreSQL забороняє перетин активних бронювань одного місця через обмеження `EXCLUDE USING gist`.
- **Оплата.** Вартість розраховується пропорційно тривалості й округлюється до копійок. Перевірка зайнятості, списання та створення бронювання виконуються в одній транзакції. За недостатнього балансу API повертає `409 Conflict`.
- **Скасування.** Власник може скасувати бронювання до його початку. Початкова сума повертається в тій самій транзакції, що й скасування. Місця з історією бронювань зберігаються, а видалення локації можливе після видалення її місць.
- **Доступність.** Redis кешує результати пошуку на 20 секунд. За недоступності Redis пошук виконується в PostgreSQL. Під час створення бронювання зайнятість завжди перевіряється в базі.
- **Нагадування.** Фоновий процес щосекунди перевіряє, для яких нагадувань настав час відправлення. Повідомлення «Ваше бронювання починається через годину» записується в лог на найближчій перевірці після планового моменту за 60 хвилин до початку. Для бронювань, створених пізніше, і після простою сервісу запис можливий, поки бронювання ще не почалося. Логи доступні через `docker compose logs -f api`.

## Інтеграційні тести

Наведені команди PowerShell запускають тести в окремому Compose-проєкті з власними PostgreSQL і Redis. Команда очищення видаляє контейнери та том цього тестового проєкту.

```powershell
docker compose -p coworking-api-tests run --rm --build --volume "${PWD}:/workspace:ro" api sh -c "python -m pip install --no-cache-dir -r /workspace/requirements-dev.txt && python -m alembic upgrade head && python -m pytest -p no:cacheprovider /workspace/tests"
docker compose -p coworking-api-tests down -v
```

Покриття включає відмову через недостатній баланс, частковий перетин і конкурентні запити на одне місце, списання та повернення великих сум, адміністративний CRUD, права на скасування й одноразове повернення коштів, пошук із Redis і момент готовності нагадування.
