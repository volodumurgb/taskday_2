# Co-working Booking API

Асинхронне REST API для мережі коворкінгів. Стек включає FastAPI, SQLAlchemy Async, PostgreSQL, Redis, Alembic, Pydantic, Docker Compose і pytest.

## Локальний запуск

Запусти Docker Desktop і виконай у корені репозиторію:

```powershell
docker compose up --build -d --wait
```

Compose запустить PostgreSQL і Redis. Коли PostgreSQL стане доступним, API застосує міграції Alembic і запустить сервер. Відкрий [Swagger UI](http://127.0.0.1:8000/docs). Для перевірки доступності є [GET /health](http://127.0.0.1:8000/health).

За замовчуванням API генерує тимчасовий ключ JWT при запуску. Щоб токени переживали перезапуск, задай власний випадковий `JWT_SECRET` у локальному `.env`. Git ігнорує цей файл.

## Робота через Swagger

1. Зареєструйся через `POST /auth/register`. Реєстрація створює гаманець із балансом `0.00`.
2. Натисни **Authorize** і введи email у полі `username` та пароль. `GET /auth/me` покаже поточного користувача й роль.
3. Для локальної перевірки адміністративних дій зареєструй окремий акаунт. Підстав його email у команду нижче. Через публічну реєстрацію самостійно вибрати роль адміністратора не можна.
4. Як адміністратор створи локацію через `POST /locations`, а в ній місце через `POST /locations/{location_id}/desks`.
5. Увійди як звичайний користувач, поповни гаманець через `POST /wallet/top-up`, а потім надішли `desk_id`, `starts_at` і `ends_at` у `POST /bookings`. Використовуй майбутній час у форматі ISO 8601 зі зміщенням, наприклад із суфіксом `Z` для UTC.
6. Перевір вільні місця через `GET /availability` із параметрами `city`, `starts_at` та `ends_at`. Власне майбутнє бронювання можна скасувати через `POST /bookings/{booking_id}/cancel`.

```powershell
docker compose exec db psql -U coworking -d coworking -c "UPDATE users SET role = 'admin' WHERE email = 'admin@example.com' RETURNING id, email, role;"
```

## Правила бронювання

- Проміжки трактуються як `[початок, кінець)`. Наступне бронювання може починатися в момент завершення попереднього.
- Ціна пропорційна тривалості й округлюється до копійок. Перевірка зайнятості, списання й створення бронювання виконуються в одній транзакції. PostgreSQL додатково забороняє перетин активних бронювань для одного місця.
- Скасування до початку бронювання повертає початкову суму в тій самій транзакції. Місця з історією бронювань зберігаються для аудиту.
- Redis кешує пошук на 20 секунд. Результат може відставати від змін на цей час. Створення бронювання завжди перевіряє актуальний стан у PostgreSQL. Якщо Redis недоступний, пошук звертається до бази.
- Фонова задача пише в лог «Ваше бронювання починається через годину» від запланованого моменту за 60 хвилин до початку. Вона перевіряє базу раз на секунду. Якщо бронювання створене менш ніж за годину до початку або сервіс був вимкнений у запланований момент, повідомлення піде на найближчій перевірці, поки бронювання ще не почалося.

Логи доступні через `docker compose logs -f api`.

## API-тести

Запускай їх в окремому Compose-проєкті з власним PostgreSQL і Redis. У PowerShell:

```powershell
docker compose -p coworking-api-tests run --rm --build --volume "${PWD}:/workspace:ro" api sh -c "python -m pip install --no-cache-dir -r /workspace/requirements-dev.txt && python -m alembic upgrade head && python -m pytest -p no:cacheprovider /workspace/tests"
docker compose -p coworking-api-tests down -v
```

Тести перевіряють нестачу коштів, частковий перетин часу, паралельні запити на одне місце, списання й повернення великих сум, CRUD із роллю адміністратора, права на скасування, одноразове повернення, пошук із Redis і час нагадування.
